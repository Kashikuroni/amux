# Дизайн: интерактивный выбор директории в форме создания сессии

Дата: 2026-05-27
Статус: согласован, готов к плану реализации
Базируется на: [2026-05-27-cm-session-manager-design.md](2026-05-27-cm-session-manager-design.md)

## Цель

Сделать шаг **dir** в форме создания сессии (`cm`) интерактивным: вместо
полностью ручного ввода пути — редактируемое поле + живой список подпапок
текущего пути, по которому можно ходить клавишами и «проваливаться» внутрь.
Закрывает желание «Tab-дополнения как в терминале», но списком вместо угадывания
префикса.

Затрагивает ТОЛЬКО шаг dir формы создания. Шаги name и agent не меняются.

## Архитектура / модули

- **Новый модуль `src/browse.rs`** — листинг подпапок; чистая логика отделена от IO:
  - `pub fn split_path(text: &str) -> (String, String)` — делит путь по последнему
    `/` на (директорная_часть_включая_слеш, хвостовой_сегмент). Без `/` →
    `("", text)`. Чистая.
  - `pub fn filter_subdirs(names: &[String], filter: &str) -> Vec<String>` —
    регистронезависимый префикс-фильтр; скрывает имена, начинающиеся с `.`, если
    `filter` не начинается с `.`; сортирует по алфавиту. Чистая.
  - `pub fn read_subdirs(base: &std::path::Path) -> Vec<String>` — `read_dir`,
    возвращает имена подкаталогов (только директории); ошибка/несуществующий путь
    → пустой `Vec`. IO.
  - `pub fn list(base: &str, filter: &str) -> Vec<String>` — связка:
    `filter_subdirs(&read_subdirs(Path::new(base)), filter)`. IO.
- **`src/app.rs`**:
  - `CreateForm` получает поля `dir_entries: Vec<String>` и `dir_selected: usize`.
  - `CreateForm::new` префиллит `dir = "~/".to_string()` и инициализирует
    `dir_entries = Vec::new()`, `dir_selected = 0` (список наполняется при входе
    в шаг dir).
  - Метод `refresh_dir_entries(&mut self)`: `let (base, filter) =
    split_path(&self.dir); self.dir_entries = browse::list(&expand_tilde(&base),
    &filter); self.dir_selected = 0;`.
  - `handle_create_key` ветвится: для `CreateField::Dir` — спец-обработка (ниже);
    для name/agent — прежнее поведение.
  - `lib.rs` объявляет `pub mod browse;`.
- **`src/ui.rs`** — `draw_create_modal`: когда `field == CreateField::Dir`, под
  тремя полями рисуется список `dir_entries` с подсветкой `dir_selected`
  (`Modifier::REVERSED`). На шагах name/agent список не рисуется.

## Поведение шага dir

Поле dir = редактируемый путь. На каждое изменение текста вызывается
`refresh_dir_entries()`.

- **Печатный символ** → добавить к `dir`, затем `refresh_dir_entries()`.
- **Backspace** → удалить последний символ `dir`, затем `refresh_dir_entries()`.
- **↑ / ↓** → двигать `dir_selected` по `dir_entries` с переносом (как в
  сайдбаре). На пустом списке — no-op.
- **Tab / →** → войти в выделенную папку: заменить хвостовой сегмент пути на
  `<имя>/` (т.е. `dir = base + selected_name + "/"`), затем
  `refresh_dir_entries()`. На пустом списке — no-op.
- **Enter** → `validate_create(name, dir, existing)`; Ok → перейти на шаг agent
  (`field = Agent`); Err → остаться в шаге dir, записать текст ошибки в
  `app.error`.
- **Esc** → отмена всей формы (как сейчас).

Списочные правила:
- Список = подпапки директорной части пути, отфильтрованные по хвостовому
  сегменту (см. `split_path` + `filter_subdirs`).
- `~` разворачивается через `expand_tilde` ТОЛЬКО для чтения ФС; отображаемый
  текст сохраняет `~`. При входе в папку (Tab/→) к отображаемому тексту
  добавляется имя подпапки, форма `~` сохраняется.
- `.`-папки скрыты, пока фильтр не начинается с `.`.
- Несуществующая база → пустой список; Tab/→ ничего не делают; Enter даёт ошибку
  валидации «directory not found».

Пример: `dir = "~/projects/pets/ag"` → `split_path` → база `~/projects/pets/`,
фильтр `ag` → список `["agents_multiplexer"]`.

## Переход между шагами (взаимодействие с существующей формой)

- name: Tab и Enter → перейти на dir (как сейчас). При переходе на dir вызвать
  `refresh_dir_entries()`.
- dir: Tab/→ = войти в папку (НЕ «следующее поле»); Enter = валидировать и перейти
  на agent. (Это сознательное расхождение с прежним «Tab=следующее поле» —
  оправдано интерактивным списком.)
- agent: Enter = submit (как сейчас); Tab = прежнее `next_field` (wrap на name),
  поведение не меняется.

## Обработка ошибок

- `read_dir` по несуществующему/недоступному пути → пустой список (не паника, не
  ошибка в UI).
- Невалидный путь на Enter → существующая `validate_create` возвращает Err →
  показывается в footer; остаёмся в шаге dir.
- Листинг больших директорий: читаются только непосредственные подкаталоги (без
  рекурсии); для типичных проектов дёшево. Чтение происходит по нажатию клавиши,
  не на тике refresh.

## Тестирование

- **Unit (чистое):**
  - `split_path`: с `/` в середине, с хвостовым `/`, без `/`.
  - `filter_subdirs`: префикс-матч, регистронезависимость, скрытие/показ
    `.`-папок в зависимости от фильтра, сортировка.
  - Навигация ↑↓ по предзаполненному `dir_entries` (wrap).
- **Интеграция (temp-dir):**
  - `read_subdirs`: создать временные подпапки (+ файл, который НЕ должен попасть
    в список) и проверить, что вернулись только директории.
  - Tab-вход: с `dir`, указывающим на temp-дерево, нажать Tab и проверить, что
    `dir` дополнился `<имя>/` и `dir_entries` обновился на содержимое.
- **UI:** snapshot-тест `draw_create_modal` в режиме dir — буфер содержит имена
  подпапок.

## Вне scope

- Рекурсивный/fuzzy-поиск по дереву.
- Left = на уровень вверх (Backspace по тексту достаточно).
- Tab-дополнение до общего префикса (заменено выбором из списка).
- Изменение шагов name/agent.

## Критерии готовности

- [ ] В шаге dir под полями виден живой список подпапок текущего пути.
- [ ] Печать фильтрует список; ↑↓ двигают подсветку; Tab/→ входят в папку;
      Enter принимает путь и идёт к agent; Esc отменяет.
- [ ] `.`-папки скрыты, пока фильтр не начинается с `.`.
- [ ] `~` разворачивается для чтения ФС, в тексте сохраняется.
- [ ] `cargo test` зелёный (новые unit + integration + ui тесты); clippy чист.
