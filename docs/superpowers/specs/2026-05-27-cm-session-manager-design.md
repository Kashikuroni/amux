# Дизайн: `cm` — CLI-менеджер сессий агентов на tmux

Дата: 2026-05-27
Статус: согласован, готов к плану реализации

## Цель

Терминальный инструмент на Rust для управления несколькими сессиями CLI-агентов
(Claude Code, aider, codex и др.) из одного места. Никакого git, никакой
оркестрации — только удобное управление tmux-сессиями. Запускается из любой
директории и не привязан к проекту с `.git`.

## Стек

- **Язык:** Rust (edition 2021)
- **TUI:** `ratatui` + `crossterm`
- **Сессии:** вызовы `tmux` через `std::process::Command`
- **Конфиг:** `serde` + `toml`
- **Бинарник:** `cm`

## Ключевые архитектурные решения

1. **Источник правды — tmux-сервер, не `cm`.** Сессиями владеет фоновый демон
   tmux. Закрытие `cm` не трогает сессии; при следующем запуске `cm` заново
   опрашивает tmux и восстанавливает список. Пересоздавать ничего не нужно.
2. **Stateless на диске** (кроме config-файла). Никакого `sessions.json`.
   Перезагрузка машины убивает tmux-сервер и все сессии — это ожидаемо и не
   решается state-файлом (живые процессы агентов перезагрузку не переживают).
3. **Метаданные хранятся в самой tmux-сессии** через user options (`@cm_*`).
   Нет второго источника правды, нет рассинхрона.
4. **Per-session агент.** Команда запуска выбирается при создании каждой
   сессии (предзаполнена дефолтом из конфига), сохраняется в `@cm_agent`.
5. **Статус running/waiting — через diff вывода pane.** На каждом тике
   сравниваем свежий `capture-pane` с предыдущим снимком в памяти.

## Структура проекта

```
agents_multiplexer/
├── Cargo.toml
└── src/
    ├── main.rs   # entry point: проверка tmux, конфиг, event loop
    ├── app.rs    # состояние UI: список, выбор, режим, кэш снимков pane
    ├── tmux.rs   # обёртка над tmux (list/new/kill/rename/attach/capture/опции)
    ├── ui.rs     # рендеринг ratatui (список, preview, footer, модалки)
    └── config.rs # чтение ~/.claude-manager/config.toml
```

## Модель данных

Сессия собирается из tmux-запроса на лету, ничего не дублируется на диске:

```rust
struct Session {
    name: String,    // = tmux session name (он же отображаемое имя)
    dir: String,     // #{session_path}
    created: i64,    // #{session_created} (unix ts)
    agent: String,   // @cm_agent
    status: Status,  // вычисляется diff'ом pane
    attached: bool,  // #{session_attached}
}

enum Status { Running, Waiting }
```

- **«Свои» сессии** помечаются `@cm_managed=1` при создании. `list-sessions`
  фильтруется по наличию этой опции — чужие tmux-сессии не показываются и не
  трогаются.
- **Снимки pane для diff** живут только в памяти `app.rs`:
  `HashMap<String /*name*/, u64 /*hash*/>`. На тике для каждой управляемой
  сессии: `capture-pane -p -t <name>` → хэш → сравнение с прошлым →
  `Running` (изменился) / `Waiting` (без изменений). Текст выбранной сессии из
  того же capture идёт в preview.

## Конфиг (`~/.claude-manager/config.toml`)

```toml
default_agent = "claude"           # предзаполняет поле agent при создании
refresh_interval_ms = 1500
agent_presets = ["claude", "aider", "codex"]  # опционально, для быстрого выбора
```

Если файла нет — берутся дефолты (`claude`, `1500`), файл не обязателен.

## Event loop (`main.rs`)

```
loop {
  ui::draw(&app)
  if event::poll(refresh_interval) {     // ждём ввод не дольше тика
    match read()? { key -> app.handle_key(key) }
  } else {
    app.refresh()   // list-sessions + capture всех + пересчёт статусов + preview
  }
  if app.should_quit { break }
}
```

`poll` с таймаутом = `refresh_interval_ms` совмещает мгновенную реакцию на
клавиши и периодическое обновление без отдельного потока.

## Режимы (state machine в `app.rs`)

`Mode::List` по умолчанию; остальные — модальные оверлеи поверх списка.

- **List:** `k`/`j` навигация (вверх/вниз), `h`/`l` скролл preview, `Enter`
  attach, `n`/`d`/`r`/`q`/`?` — переходы. Стрелки тоже принимаются, но в
  подсказках указаны vim-клавиши.
- **Create:** форма из 3 полей по очереди — *name* → *dir* → *agent*
  (предзаполнено `default_agent`). `Tab`/`Enter` — следующее поле, `Esc` —
  отмена. Валидация: имя непустое и не дублирует существующую сессию; dir
  существует (иначе ошибка, остаёмся в форме); `~` разворачивается.
- **Rename:** inline-редактор поверх выбранной строки → `tmux rename-session`.
- **ConfirmDelete:** `Kill session "<name>"? (y/n)` → `tmux kill-session`.
- **Help:** оверлей со списком клавиш, любая клавиша закрывает.

## Создание сессии

```
tmux new-session -d -s <name> -c <dir> "<agent>"
tmux set-option -t <name> @cm_managed 1
tmux set-option -t <name> @cm_agent "<agent>"
```

## Attach / detach

`cm` владеет терминалом (raw mode + alt-screen). По `Enter`:

1. Выходим из TUI: `disable_raw_mode`, покидаем alt-screen, показываем курсор.
2. Запускаем `tmux attach-session -t <name>` как foreground-ребёнок,
   наследующий stdin/stdout, и ждём завершения (detach `Ctrl-B D`).
3. Возвращаемся: заново raw mode + alt-screen, форсим `refresh()` и перерисовку.

**Edge-case вложенного tmux:** если `cm` запущен внутри tmux (`$TMUX` задан),
вложенный attach ломается. Обнаруживаем и показываем понятное сообщение
(«detach из текущего tmux перед attach»), а не падаем молча.

## Обработка ошибок

- Нет `tmux` в PATH при старте → понятная ошибка и выход с ненулевым кодом
  (до входа в TUI).
- Любая tmux-команда вернула ошибку (имя занято, сессия исчезла) → показываем
  одной строкой в footer (transient), цикл продолжается.
- `capture-pane` по исчезнувшей сессии → она выпадает из списка на следующем
  `refresh`.

## Тестирование

- **Unit (чистая логика):** парсинг конфига, разворачивание `~`, валидация
  формы создания, diff-статус по двум снимкам, парсинг вывода `list-sessions`.
- **Интеграционные (`tmux.rs`), гард по наличию `tmux`:** round-trip
  new → list (видим `@cm_managed`) → rename → capture → kill на временных
  сессиях с уникальным префиксом, с очисткой в конце.
- **UI (`ui.rs`):** снапшот-рендер через `ratatui::TestBackend` для пары
  состояний (список из 3 сессий, модалка создания). Необязательно.

## Клавиши

| Клавиша | Действие |
|---------|----------|
| `k` / `j` | Навигация по списку (вверх / вниз) |
| `h` / `l` | Скролл preview (отложено, не в v1) |
| `Enter` / `o` | Подключиться к сессии (attach) |
| `n` | Создать новую сессию |
| `d` | Удалить сессию (с подтверждением) |
| `r` | Переименовать сессию |
| `q` | Выйти (сессии остаются в фоне) |
| `?` | Показать помощь |

## UI/UX направление (референс claude-squad)

Целевой look & feel — как у [claude-squad](https://github.com/smtg-ai/claude-squad),
адаптированный под отсутствие git. Воспроизводим:

- **Фуллскрин.** Приложение занимает весь терминал (alt-screen ratatui) и
  переразмеряется вместе с окном. Никакого inline-вывода в текущий буфер.
- **Заголовок/лого** сверху (название инструмента), как шапка у claude-squad.
- **Левый сайдбар — список сессий, 25% ширины.** Каждая строка: индикатор
  статуса + имя сессии (+ усечённый `dir`/агент второй строкой, если влезает).
  Выбранная строка подсвечена. Навигация `k`/`j` (стрелки тоже принимаются).
- **Статус-индикаторы как в claude-squad:** у `Running` — анимированный спиннер,
  у `Waiting` — статичный «готов»-маркер. (В claude-squad есть ещё `paused`; у
  нас его нет.)
- **Правая панель — 75% ширины.** В claude-squad тут табы **Preview** и **Diff**;
  **у нас git нет, поэтому таба Diff нет** — правая панель показывает только
  Preview (живой вывод агента, `tmux capture-pane`). Заголовок панели — имя и
  `dir` выбранной сессии.
- **Нижнее меню хоткеев** на всю ширину, сгруппированное по смыслу (как у
  claude-squad: управление сессиями / действия / навигация).

Отличия от claude-squad по сути: нет git/worktree → нет diff-таба, нет
commit/push/checkout/resume; вместо них — переименование (`r`). Detach из
сессии — штатным tmux `Ctrl-B D` (а не `ctrl-q`).

## Макет интерфейса

**Это схема компоновки и пропорций (1/4 сайдбар + 3/4 preview), а не финальный
вид** — визуальный стиль берём из claude-squad (см. раздел выше).

```
┌─ cm ──────────────────────────────────────────────────────────────────────────┐
│ ┌─ sessions (3) ────┐ ┌─ preview: project-a · ~/work/proj-a ────────────────┐ │
│ │ ⠋ project-a       │ │ > Analyzing files...                                │ │
│ │ ● project-b       │ │ Found 12 TypeScript files                           │ │
│ │ ⠋ bugfix-1        │ │ Working on auth.ts                                  │ │
│ │                   │ │ ...                                                 │ │
│ │                   │ │                                                     │ │
│ └───────────────────┘ └─────────────────────────────────────────────────────┘ │
│ sessions: [n] new  [d] kill  [r] rename   actions: [↵/o] attach   nav: [j/k] [q]│
└─────────────────────────────────────────────────────────────────────────────────┘
```

`⠋` — спиннер у `Running`, `●` — маркер `Waiting`. В узком сайдбаре полный путь
не помещается, поэтому `dir` уходит в заголовок preview.

## Вне scope (v1)

- Git worktree, оркестрация/межагентная коммуникация, синхронизация контекста.
- State-файл и восстановление сессий после перезагрузки машины.
- Tab-completion пути при вводе dir (nice-to-have, не в v1).
- Скролл preview по `h`/`l` (отложено, не в v1).
- Web/GUI, yolo-режим авто-принятия.
